# Local persistence and recovery
Node 22 and its built-in SQLite module reuse the existing D1 run-store contract. Dedicated local database only, migrations transactional with application ID and version checks. The local CLI supports enqueue, status and one-pass drain. Example: node scripts/local-runner.mjs enqueue "Create an offline static page", then node scripts/local-runner.mjs drain. Use a single drain process; this is not a system-wide agent lock or a background service. The database contains prompts and artifacts: protect its directory with OS access permissions; never commit it. The CLI does not execute generated code, write GitHub, or send data to cloud providers. Review and blocked runs are not automatically retried. After abrupt termination a lease must expire before the next drain can recover a run. Live Windows/Ollama tests, continuous scheduling and arbitrary repository execution remain pending. No production changes.
