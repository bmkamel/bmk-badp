# Agent execution boundary — initial orchestration
Aider and OpenCode are accepted engine identifiers. The orchestration layer requires a trusted project registry, an explicitly enabled project, an independently provisioned execution backend and independent artifact review. It requests no network, no credentials, no host mounts, no publishing, and bounded resources. These policy fields are a contract, not enforced isolation. The current implementation has no concrete backend, so no agent is launched. Do not substitute an ordinary child process for isolation.

The proposed backend should use a disposable guest with a pinned toolchain and restricted filesystem and egress. Local inference requires a separately controlled broker: do not grant general network access or pass host tokens to the guest. Review the exact artifact in a trusted process and reject mismatched evidence. No agent-driven Git push or production writes. Real Windows hardware capability, backend resource limits, model access, cancellation and CI verification remain pending. The 4096 MiB guest cap is provisional and must be benchmarked on the 8 GB host.
