# Repository execution admission — R3 early slice
A proposed repository job now requires an immutable base SHA, restricted DEV branch name, bounded goal and approved engine identifier. Proposed changes are limited to source, tests and docs, with path, size, file count and case-collision checks. Configuration, database migrations, workflows, deletions and secret-like paths are denied in this initial scope.

This module is pure validation, not a trusted repository authorization or filesystem sandbox. Caller-supplied paths and sizes must be replaced by independently measured Git diff metadata; actual tree modes, symlinks, submodules, binary content, path aliases, secret scanning and per-project repository allowlists must be checked before publication. Valid source code can still be hostile. Do not execute generated code or invoke Aider/OpenCode until isolation, environment scrubbing, network restrictions, resource limits and independent test gates exist. No agent invocation, Git push, deployment or live provider call is added here.
