# BADP engineering queue
The authenticated dashboard submits a typed owner request to D1. The scheduled GitHub-hosted worker claims one item with an expiring lease and retries at most three times. The first two work orders are a system-aware dashboard theme and a keyboard shortcut. They modify only `preview/chat-page.mjs`. The latter is queued automatically after the first deployment has been verified.

## Research and decision record
- MDN, color-scheme property, consulted 2026-11-28. It documents how operating-system theme preference and native control rendering interact. BADP uses that preference and preserves RTL. The executor checks the source marker before generating the patch. https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/color-scheme
- GitHub, GITHUB_TOKEN and event rules, consulted 2026-11-28. GitHub suppresses a normal push trigger for automation-token commits. Dispatch the existing deployment workflow explicitly and check the resulting Worker revision. https://docs.github.com/en/actions/concepts/security/github_token
- Cloudflare, coding agents in sandboxes, consulted 2026-11-28. Its proxy design keeps secrets outside agent workspaces. Reuse that boundary rather than adopting a new hosted agent runtime for this typed lane. https://developers.cloudflare.com/sandbox/coding-agents/

## Operating boundaries
The trusted code generates the change. Task text cannot supply shell commands, Git ref names, credentials, or candidate source. Repository regression tests run as a separate step without publication credentials. Publication rechecks the allowed path, exact content, signed-out deployment smoke tests, PR head and immutable source revision. Reviews of open-ended model-generated diffs remain a separate capability.

Disable the engineering workflow or set repository variable `BADP_ENGINEERING_PAUSED=true` to stop new claims. Queued tasks expose pause/resume in the dashboard. GitHub concurrency serializes workers. A failed deployment verification retains its PR and merge SHA for recovery and never labels the task verified. The deployment workflow captures the prior healthy single-version Worker. On a failed smoke test it restores that version only if the failing SHA is still active and the recorded deployment is its immediate predecessor. It does not force a rollback or restore D1 state. The recovery selector is regression-tested; a destructive production fault is not injected. The Git branch remains subject to repository protections.

- Cloudflare deployment versions preserve code and bindings independently of D1 state. The rollback guard uses that distinction and verifies the recovered source SHA. https://developers.cloudflare.com/workers/versions-and-deployments/

The authenticated dashboard can pause new claims and merges. A publication that has already merged still finishes deployment verification. While idle, the worker records at most one policy/source/deployment inspection per UTC day. The record includes the blueprint and charter digests, observed release, allowlisted official source, and workflow link. Source availability is not a general assessment of upstream guidance.

The dashboard discovery rule inspects the checkout for a missing theme selector after system theme support exists. It records a typed recipe once per owner. The scheduler verifies the official color-scheme reference and the exact one-file candidate before opening the PR, using the same merge and deployed-SHA gates.

## R1 model tasks

Migration 0013 adds model tasks and owner requests in ENGINE_DB. The existing engineering schedule checks two public landing controls for language and theme issues. It reads MDN or Unicode CLDR, records the content digest, observation and decision, and claims a finding under a lease. Each finding has one immutable scope and one row per owner. The model receives only the public label dictionary and its task. The publisher accepts only a reviewed JSON literal module, verifies its behavior offline, and checks both the deployed revision and the affected public link texts. Broader source edits require their own verifier.

The dashboard engineering inspection option records the original command privately. The request and the resulting engineering tasks have separate statuses. A completed inspection can find zero eligible changes. Commands outside the supported inspection scope remain visible for review.

Model generation uses the existing daily D1 allowance. OpenRouter requires zero price and observed zero cost. Groq requires a separately verified free organization and the repository variable BADP_GROQ_FREE_VERIFIED. A quota refusal defers the task until the next UTC day and preserves its retry allowance. The scheduled advisory yields capacity to pending engineering tasks. A verified model task dispatches the next queue run. The schedule also resumes after an interrupted dispatch. Run links and provider names are available from the engineering API. Unit tests and the existence of a queued row do not certify a live model cycle.
